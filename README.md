## Setup

```bash
git clone https://github.com/dymasius12/DSA.git
cd DSA
python3 -m pip install -r requirements.txt
./check all        # every reference solution and write-up should pass
```

| Command | What it does |
|---|---|
| `./review` | what's decayed, and what to do today |
| `./check 01` · `./check 01 two_sum` | test your practice stubs (a module, or one problem) |
| `./check all` | verify every solution and index (what CI runs) |
| `./log "what I did" 30` | record a session in PROGRESS.md |
| `./sync` | regenerate the indexes and progress after adding a write-up |

## How it's organized

Every topic exists at three depths, plus real problems to apply it to:

| Folder | What's in it | Use it to |
|---|---|---|
| [`cheatsheets/`](cheatsheets/) | one screen per topic | reload fast |
| [`notes/`](notes/) | the full explanation | learn it the first time |
| [`problems/`](problems/) + `tests/` | stubs with tests | practise |
| [`solutions/`](solutions/) | annotated reference answers | compare, after trying |
| [`leetcode/`](leetcode/) | real problems, solved and reviewed | apply it, and relearn without spoilers |
| [`templates/`](templates/) | starting points for new write-ups | add to the repo |
| [`tools/`](tools/) | the problem catalog and the index generator | keep everything in sync |

<details>
<summary><b>Why this repo exists</b></summary>

<br>

I've learned this material before, more than once. Then life gets busy, I stop
for a few months, and coming back feels like starting from zero. *That
feeling* is the real problem: it's what stops me opening it at all.

DSA knowledge evaporates when it's stored as **thousands of loose problems**.
Loose things decay. Patterns compress, and compressed things reload fast. So
each topic is kept at three depths, in order of how fast they fade:

| Layer | Fades |
|---|---|
| `problems/`: the reps | **fast** |
| `notes/`: the explanation | slowly |
| `cheatsheets/`: one screen | **barely** |

Coming back means reloading the smallest, most durable layer and letting the
rest come back behind it. `./review` then scores each topic by decay (time away
× how shaky it was) and says where to start, which removes the hardest
decision.

</details>

<details>
<summary><b>Notes for readers</b></summary>

<br>

- The **[pattern map](cheatsheets/_patterns.md)** stands on its own: a
  trigger → pattern table plus working templates, assuming nothing else here.
- Starting near zero? [`notes/00_foundations.md`](notes/00_foundations.md)
  assumes nothing.
- Everything is checked: `./check all` runs every reference solution and
  write-up, and CI runs it on every push. Code snippets in the cheatsheets were
  executed before being committed.
- Problem IDs, links, and difficulties in [PROBLEMS.md](PROBLEMS.md) are
  checked against LeetCode (`python3 tools/verify_catalog.py`).
- Found something wrong or unclear? An issue is welcome.

</details>
